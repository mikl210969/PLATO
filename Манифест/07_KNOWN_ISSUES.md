# 🚨 Known Issues & Tech Debt (Бэклог Платформы)

Этот документ представляет собой исчерпывающий список проблем, архитектурных долгов и точек роста, выявленных в ходе полного ревью кода платформы `PLAT_WALLS_NEW`.

## 🔴 БЛОКЕРЫ (Critical / Blockers)
*Проблемы, которые гарантированно приведут к потере денег, сливу депозита или компрометации аккаунта. Требуют немедленного исправления.*

### 💰 Торговая логика и Математика
- [ ] **Инвертированный Risk/Reward в `trading.json`.** 
  - *Суть:* `atr_multiplier_sl = 20.0`, а `atr_multiplier_tp1 = 2.0`. Стоп-лосс в 10 раз больше Тейк-профита. Платформа рискует $10, чтобы заработать $1.25.
  - *Действие:* Исправить множители (например, SL=2, TP1=4, TP2=6) или сделать ATR динамическим.
- [ ] **Мёртвый Глобальный Risk-Менеджмент (`risk.json`).**
  - *Суть:* Параметры `max_daily_loss`, `max_drawdown`, `max_trades_per_hour` загружаются, но **нигде в коде не проверяются**. Платформа будет торговать до полного слива при серии убытков.
  - *Действие:* Внедрить `GlobalRiskManager` или добавить проверки лимитов в `Orchestrator._on_signal()`.
- [ ] **`reduce_only=False` для TP/SL ордеров.**
  - *Суть:* `RiskManager` выставляет TP и SL без флага `reduce_only`. Если TP1 сработал, а цена развернулась, TP2 или SL могут **открыть новую позицию** в противоположную сторону вместо закрытия.
  - *Действие:* Всегда передавать `reduce_only=True` при выставлении защитных ордеров.

### 🔐 Безопасность
- [ ] **Утечка API-ключей.**
  - *Суть:* Ключи лежат в `config/exchange.json` в открытом виде. Файл не в `.gitignore`.
  - *Действие:* Перенести ключи строго в `secrets.json`, добавить `exchange.json` и `secrets.json` в `.gitignore`, убрать fallback на `exchange.json` в `main.py`.

### 🔄 Жизненный цикл и Устойчивость
- [ ] **Отключен `RecoveryManager`.**
  - *Суть:* В `main.py` строка `await self.recovery_manager.recover()` закомментирована. При перезапуске платформа "забывает" про открытые позиции и выставленные TP/SL на бирже.
  - *Действие:* Раскомментировать, протестировать сценарии восстановления.
- [ ] **Стратегия `Breakout` мертва.**
  - *Суть:* Стратегия требует `context['candles']`, но `main.py` не загружает историю свечей и не передаёт их в контекст. Стратегия всегда возвращает `None`.
  - *Действие:* Добавить фоновую загрузку свечей (REST `/klines` или WS `@kline`) и пробрасывать их в `context`.
- [ ] **Отключен `get_order_status()` в `Trader`.**
  - *Суть:* Метод временно отключён (всегда возвращает `None`). Из-за этого `RecoveryManager` не может проверить статус ордеров, зависших в `ORDER_SENT`.
  - *Действие:* Активировать метод и корректно обработать ответы API.

## 🟠 ВЫСОКИЙ ПРИОРИТЕТ (High Priority)
*Серьёзные архитектурные изъяны, проблемы с целостностью данных и риски бана API.*

### 📊 Данные и PnL
- [ ] **PnL всегда равен нулю.**
  - *Суть:* При закрытии по TP/SL в `StateManager` передаётся `gross_pnl=0`. Статистика сделок не ведётся.
  - *Действие:* Брать PnL из WS `ACCOUNT_UPDATE` или запрашивать историю сделок (`/fapi/v1/userTrades`).
- [ ] **Статический ATR.**
  - *Суть:* `atr_value = 0.5` берётся из конфига. Уровни SL/TP не адаптируются к текущей волатильности рынка.
  - *Действие:* Реализовать динамический расчёт ATR на основе последних N свечей.
- [ ] **Отсутствие переноса SL в безубыток.**
  - *Суть:* Заявлено в описании, но после срабатывания TP1 код не отменяет старый SL и не выставляет новый по цене входа.
  - *Действие:* Реализовать логику в `Orchestrator` (по событию `TP1_FILLED`) или в `RiskManager`.

### 🏗️ Архитектура и Целостность
- [ ] **REST-опрос позиции каждые 2 секунды.**
  - *Суть:* В цикле `main.py` делается `rest.get_position()`. Это 1800 запросов в час. Риск получения бана IP от Binance (Weight limits).
  - *Действие:* Убрать запрос из цикла. Состояние позиции должно обновляться **только** из WS `ACCOUNT_UPDATE`.
- [ ] **`JsonLogger` пишет битый JSON при краше.**
  - *Суть:* Файл `platform_log.json` является валидным массивом только после вызова `close()`. При `kill -9` или краше файл остаётся битым.
  - *Действие:* Перейти на формат **JSONL** (JSON Lines), где каждая строка — независимый JSON.
- [ ] **`PassportRepository` не использует атомарную запись.**
  - *Суть:* Прямая перезапись файла через `open('w')`. При падении во время записи файл паспорта повреждается.
  - *Действие:* Писать во временный файл `.tmp`, затем использовать `os.replace()`.
- [ ] **Статус `UNKNOWN` не обработан в `StateManager`.**
  - *Суть:* Если паспорт попал в `UNKNOWN`, из него нет разрешённых переходов. Паспорт "застревает".
  - *Действие:* Добавить переходы из `UNKNOWN` в `OPEN` / `CLOSED` / `FAILED`.

## 🟡 СРЕДНИЙ ПРИОРИТЕТ (Medium Priority)
*Технический долг, отсутствие гибкости, нарушения чистоты кода.*

### ⚡ Производительность и Event-Driven
- [ ] **Polling вместо Event-Driven для стратегий.**
  - *Суть:* `main.py` опрашивает стратегии каждые 2 секунды (`asyncio.sleep(2)`). Задержка реакции на рынок.
  - *Действие:* Перевести вызов стратегий на колбэк `depthUpdate` (реагировать на изменение стакана мгновенно).
- [ ] **Отсутствие Retry-логики и Rate Limiter в REST.**
  - *Суть:* При сетевой ошибке ордер не отправляется повторно. Нет защиты от `429 Too Many Requests`.
  - *Действие:* Добавить `tenacity` (или аналог) для ретраев и `asyncio.Semaphore` для rate limiting.

### 🧹 Чистота кода и Рефакторинг
- [ ] **Дублирование кода подписи (HMAC) в `BinanceRestClient`.**
  - *Суть:* Логика подписи скопирована в 5+ методов. Есть общий `_request()`, но он не используется.
  - *Действие:* Переписать все методы отправки ордеров через единый `_request(method, path, params, signed=True)`.
- [ ] **Отладочные `print()` в критических модулях.**
  - *Суть:* `Orchestrator`, `RiskManager`, `REST` используют `print()` с эмодзи вместо `JsonLogger`.
  - *Действие:* Заменить на `self.logger.info()` или `self._log()`.
- [ ] **Мёртвые параметры в стратегиях.**
  - *Суть:* `min_confidence`, `min_wall_volume` (в Absorption), `breakout_threshold` читаются из конфига, но не используются.
  - *Действие:* Либо реализовать их использование, либо удалить из конфигов и конструкторов.
- [ ] **Захардкоженные `confidence` и пороги.**
  - *Суть:* Уверенность сигнала (0.6 / 0.7) и пороги (1.5, 0.5) не зависят от рыночных условий и не настраиваются.
  - *Действие:* Внедрить динамический расчёт confidence на основе объёмов/расстояний.
- [ ] **`ChannelRouter` — мёртвый код.**
  - *Суть:* Инициализируется, но не используется, так как методы отправки ордеров через WS не реализованы.
  - *Действие:* Либо реализовать WS API (Binance Order Routing), либо удалить Router и не вводить в заблуждение.
- [ ] **`FAILED` статус блокирует символ.**
  - *Суть:* `PassportManager.get_active()` не исключает `FAILED`. Символ остаётся "занятым" навсегда.
  - *Действие:* Добавить `FAILED` в список терминальных статусов при фильтрации.

### 🔄 Логика состояний
- [ ] **Нет перевода в `PARTIAL_CLOSE` при срабатывании TP1.**
  - *Суть:* При `TP1_FILLED` размер позиции уменьшается, но статус паспорта остаётся `OPEN`.
  - *Действие:* Вызывать `state_manager.handle_event(passport, "PARTIAL_CLOSE")`.
- [ ] **Хрупкая схема `client_order_id`.**
  - *Суть:* `Orchestrator` определяет тип ордера по префиксу строки (`TP1_`, `SL_`).
  - *Действие:* Добавить в структуру ордера явное поле `role: 'ENTRY' | 'TP1' | 'TP2' | 'SL'`.
- [ ] **`_healthy` не инициализирован в `BinanceWsAdapter`.**
  - *Суть:* Поле создаётся только в `health_check_loop()`. Вызов `is_healthy()` до старта цикла вызовет `AttributeError`.
  - *Действие:* Добавить `self._healthy = False` в `__init__`.

*Мелкие улучшения, стилистика, подготовка к масштабированию.*
